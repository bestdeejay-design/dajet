## 1. Что было сломано (исправлено в этом репозитории)

### 1.1. Битый аудиофайл в плейлисте — реальная ошибка воспроизведения

`albums/The third album/Незнакомец в Метро (Stranger on the Metro) (Cover 2).m4a`
весит **2 байта** (внутри просто перевод строки). Файл загрузки не пережил —
это типичный результат прерванной загрузки/экспорта.

Последствия: трек попадал в `library.json`, пользователь видел в плеере
ошибку «Формат не поддерживается» и всё зависало в состоянии «играет»,
кнопка показывала паузу, хотя музыки не было.

Что сделано:
- трек исключён из `library.json` (генератор теперь отбраковывает файлы,
  которые не похожи на валидное аудио и предупреждает о них в логе сборки);
- сам файл на диске **не удалён** — перезалейте его корректной версией,
  и он вернётся в галерею автоматически;
- плеер теперь умеет справляться с такими ситуациями (см. п. 3).

### 1.2. Внешняя зависимость от CDN, которая работает в России нестабильно

Сайт тянул GSAP с `cdnjs.cloudflare.com` (Cloudflare) — единственная
внешняя зависимость. У Cloudflare в РФ с 2024–2025 гг. DPI-ограничения и
подмены DNS, `cdnjs.cloudflare.com` фигурировал в исследованиях
DNS-аномалий (te-st.org, август 2026). Когда библиотека не загружалась,
в консоли появлялась ошибка и анимация галереи не срабатывала.

Что сделано:
- CDN полностью удалён из `index.html` (вместе с preconnect);
- появление карточек переписано на чистый CSS со ступенчатой задержкой
  (`--i`), с уважением к `prefers-reduced-motion`;
- внешних запросов при загрузке страницы больше нет вообще.

### 1.3. Неверный домен в метатегах (SEO, превью в соцсетях, поиск)

В `index.html` canonical, `og:url`, `og:image`, `twitter:image` и JSON-LD
указывали на `https://dajet.ru`, а сайт живёт на **dj1.ru**. При этом
`dajet.ru` теперь отдаёт совсем другой сайт (портфолио, репозиторий `ksu`).
То есть превью ссылки в мессенджерах/соцсетях подтягивало чужую страницу,
а поисковикам сообщался неверный канонический адрес.
CNAME и настройки GitHub Pages при этом уже указывали на dj1.ru.

Что сделано: все адреса приведены к `https://dj1.ru/`, добавлен JSON-LD
с картинкой, `og:image:alt`, `og:site_name`.

### 1.4. Мёртвый легаси-мусор в репозитории

- папка `data/` — 11 файлов (`Album Second.js`, `Album%20Second.js`, …)
  от старой архитектуры, когда каждый альбом был отдельным JS-файлом.
  На них нет ни одной ссылки в проекте, `ALBUM_TRACKS` нигде не читается →
  **удалено**;
- `albums/*/test.txt` (6 пустых файлов «test») публиковались как часть
  сайта → **удалено**;
- `albums/Paradise Lost/рай не лечитю.txt` (текст песни) оставлен —
  это ваш контент, просто не участвует в галерее.

### 1.5. Ошибочный элемент интерфейса: ссылка на обложку-заглушку

При сбое аудио в блоке трека выводилось сообщение вместо названия трека,
а рядом оставалась «играющая» иконка. Теперь состояние приводится в
порядок: иконка переключается на «play», появляется заметное сообщение,
трек помечается в плейлисте как недоступный, происходит автопереход
(но не более 3 сбоев подряд — защиты от зацикливания).

## 4. Требует вашего решения (вне репозитория)

### 4.1. DNS для dj1.ru — только одна A-запись 🔴

```
dj1.ru → 185.199.108.153     (сейчас)
```

GitHub Pages требует **четыре** A-записи для отказоустойчивости:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Плюс (по желанию) четыре AAAA-записи и `www` → CNAME `dj1.ru` (последнее
у вас уже есть). С одной записью сайт держится на одном узле и, что важнее,
именно из-за неполного DNS GitHub Pages сейчас показывает статус
сертификата `dns_changed` — «Detected a change to DNS settings. Requesting
a new certificate» (текущий сертификат действует до 2026-11-17).
Рекомендую привести записи к каноническим — это в панели вашего DNS-провайдера.

### 4.2. Домен: dj1.ru — окончательный? 🟡

Галерея теперь на `dj1.ru`, а `dajet.ru` отдаёт портфолио (репозиторий
`ksu`). Если задумывалось наоборот (для бренда DAJET логичнее `dajet.ru`),
это надо решать осознанно: сменить CNAME + домен в GitHub Pages и
одновременно поменять адреса в `index.html`. Скажите — сделаю.

### 4.3. Размер репозитория и лимиты GitHub Pages 🟡

- `albums/` — 664 МБ (652 МБ из них — аудио);
- `.git/` — 605 МБ, суммарно репозиторий ~1,3 ГБ.

Лимит опубликованного сайта на GitHub Pages — ~1 ГБ, репозитория — 1 ГБ
(мягкий), трафика — 100 ГБ/мес. Мы пока в лимит укладываемся (~665 МБ), но
запас небольшой: ещё 5–7 альбомов в текущем качестве — и упрёмся.

Варианты (это уже «более серьёзная работа», если понадобится):
1. новые альбомы выкладывать в 96–128 kbps (сейчас средний 121 kbps —
   уже близко к оптимуму);
2. вынести аудио на внешнее хранилище (S3/R2/Bunny/Selectel) и оставить в
   GitHub только сайт + обложки — тогда галерея сможет расти без предела;
3. сжать существующую коллекцию — но это перекодирование 12,4 часов звука
   (репозиторий придётся переписывать, история `.git` тоже тяжёлая).

### 4.4. Не используется 35 картинок (~1,3 МБ) 🟢

В `albums/` лежат обложки, которые не привязаны ни к одному треку
(например, `Psychedelic Vibe Lost Century/Rewind (Black Hole Sun Style).jpg`).
Возможно, вы планировали их использовать. Если нет — удалю по вашему слову.

### 4.5. Формат аудио 🟢

Все 227 треков — `.m4a` (AAC). Это играет в Chrome, Safari, Edge и в
Firefox на Windows/macOS. На некоторых сборках Firefox в Linux без
системных кодеков AAC может не воспроизводиться — там понадобился бы
mp3-фолбэк (это +диск и трансcoding). Пока считаю риском низкого
приоритета, но пусть будет в списке.

### 4.6. Проверить MIME-тип на хостинге 🟢

Из этой песочницы нет прямого доступа к заголовкам dj1.ru. Откройте
DevTools → Network → любой `.m4a` и убедитесь, что `Content-Type: audio/mp4`
и есть `Accept-Ranges: bytes` (нужно для перемотки). Если MIME окажется
`application/octet-stream` — напишите, подберём решение.

## 6. Второй проход аудита — глубокая проверка коллекции

Проведён по запросу, с упором на сохранность коллекции и качество звука.

### 6.1. Коллекция цела — проверено побитово ✅

- `git fsck` — ошибок нет, повреждённых объектов нет;
- **все 501 файл коллекции побитово совпадает с содержимым git-репозитория**
  (сверка `git hash-object` по каждому файлу, включая имена с кириллицей,
  апострофами и диакритикой) — то есть в репозитории лежит ровно то, что
  вы загружали, и ничего не подменено;
- **все 228 аудиофайлов полностью декодированы** (ffmpeg, не только проверка
  заголовков): 227 декодируются чисто от начала до конца, единственный
  нечитаемый — тот самый 2-байтный файл, который уже исключён из галереи.
  Обрезанных или «полузагруженных» файлов нет;
- 272 изображения — валидные JPEG/WebP;
- почти пустых или беззвучных треков нет (все 12,4 часа звука содержательны).

### 6.2. Звук: громкость и динамика

Замер по EBU R128 для всех 227 треков (`loudnorm`):

| Показатель | Значение |
|---|---|
| Интегрированная громкость | от −14,8 до −9,0 LUFS, медиана −13,2 |
| Разброс между треками | **5,8 LU** — заметно на слух |
| Динамика (LRA) | от 3,2 до 17,9 LU, медиана 6,2 |

Разброс 5,8 LU — это когда после тихой песни следующая «бьёт по ушам».
Поэтому добавлено **выравнивание громкости**: уровень каждого трека вшит
в `library.json`, плеер подстраивает громкость в пределах +6/−12 дБ
(кнопка «Ровно» в плеере). Кнопка отключается, если хочется слушать
«как в файле».

Побочно выяснилось: у 180 из 227 треков истинный пик выше 0 dBTP
(до +1,9) — это громкий мастеринг с интерсэмпловым клиппингом, а не
повреждение файлов. Когда плеер делает трек тише, клиппинг на выходе
уже не возникает. Если когда-нибудь будете делать ремастер — стоит
целиться в −1 dBTP и −14 LUFS, но сейчас это не обязательно.

### 6.3. Тексты песен были заперты в метаданных

У 11 треков (весь альбом **Spanish Nights**) в файлах вшиты тексты песен
(тег `LYRICS`), а также `TITLE`, `ARTIST`, `COMMENT` вида
`PRODUCER_MODEL:FUZZ-2.0` и `DESCRIPTION` с описанием аранжировки. Сайт их
не показывал — теперь в плеере есть кнопка **«Текст»**, которая открывает
панель с текстом (активна только там, где текст есть).

### 6.4. Дубликаты файлов

14 групп побайтово одинаковых файлов, 30 файлов, «лишний» объём **52,8 МБ**.
Есть тройные копии, например `can you hear` лежит в трёх альбомах,
`Short Circuit (Psychedelic Jazz)` — тоже в трёх, `317 AM Ritual` /
`3:17 AM Ritual` / `3-17 AM Ritual` — один и тот же файл под тремя именами.

Ничего не удалял: копия в другом альбоме может быть задумана.
Посмотреть список: `node tools/report-duplicates.js`.

### 6.5. Что ещё нашлось и исправлено

- **Случайное дублирование блока в `player.css`** — правка легла внутрь
  медиазапроса и часть правил не применялась. Устранено, оба CSS-файла
  теперь проверены парсером `css-tree` (0 ошибок разбора).
- **Битые обложки** показывались «сломанной картинкой». Теперь любая
  не загрузившаяся обложка (альбома, трека, в плейлисте) подменяется
  аккуратной заглушкой.
- **Media Session заявляла размер 512×512** для всех обложек, хотя часть
  из них 1024×1024 — на экране блокировки телефона обложка могла не
  показываться. Теперь заявлены оба размера.
- Добавлены `-webkit-backdrop-filter` (Safari) — размытие плеера и карточек
  работает и там.
- Проверена совместимость синтаксиса: `?.`, `??`, `replaceAll` не
  используются, так что сайт работает и в Safari 13 / старых Android.
- Мобильная раскладка: на узких экранах кнопка скина скрывается, чтобы
  «Ровно», «Текст» и «Плейлист» не сжимались.

### 6.6. Защита коллекции — чтобы «исчезновение» не повторилось

- **`CHECKSUMS.sha256`** — контрольные суммы всех 501 файла коллекции,
  лежат в репозитории. Проверка: `node tools/verify-checksums.js`
  (инструмент проверен и на подпорченном файле — расхождение ловится).
- **Недельный workflow** «Проверка целостности коллекции»: каждое утро
  понедельника GitHub сам сверяет все файлы и, если что-то повредилось
  или пропало, открывает issue с отчётом. Ничего не нужно делать руками.
- **`tools/make-backup.sh`** — резервная копия коллекции и всей истории
  репозитория в один файл (git-bundle, 604 МБ). Проверено: из копии
  восстанавливается полноценный репозиторий (501 файл, вся история).

  ```bash
  bash tools/make-backup.sh ~/Backups/dajet            # копия истории
  bash tools/make-backup.sh /media/usb/dajet --with-media  # + архив файлов
  git clone ~/Backups/dajet/dajet-2026-10-05.bundle dajet-restored
  ```

  **Рекомендация:** сделайте копию на внешний носитель или в облако прямо
  сейчас — репозиторий на GitHub это одна точка отказа.

### 6.7. Готовность к росту коллекции

Вы упомянули, что будете создавать новые треки, — вот что уже готово
и что стоит знать:

- **Готово:** `config.js` → `mediaBase`. Если аудио перерастёт лимиты
  GitHub (1 ГБ), вы выкладываете папку `albums` на любое хранилище
  (S3, R2, Selectel, Bunny) и вписываете адрес одной строкой — сайт
  продолжает работать без других правок.
- **Кэш анализа:** генератор пересчитывает громкость и тексты только для
  файлов, которые изменились (сравнение по размеру), поэтому сборка не
  будет каждый раз прогонять часы звука.
- **Пределы, о которых стоит помнить:** при 10 000 треков коллекция займёт
  ~29 ГБ — это точно внешнее хранилище, а не GitHub. И если в одном
  альбоме окажется больше ~500 треков, понадобится виртуализация списка
  в плейлисте (сейчас рисуются все элементы сразу — при 58 треках это
  незаметно).
